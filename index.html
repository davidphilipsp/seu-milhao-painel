behind Seu Milhão

Seu Milhão is a Brazilian prize-draw brand. It sells through partner bars, individual affiliates and sports teams, and runs its own traffic, CRM, support and finance. This page maps the single system that runs all of that. I designed it and built it with Claude Code as my pair programmer, from August to November 2026.

Claude inside the product

Where the panel calls an LLM, and the guardrails

The AI works in narrow lanes, each with a written rule about what it may touch.

Support triage

claude-haiku-4-5 · every minute, via scheduler

Reads an open support conversation and suggests type, root cause, urgency and a one-line summary.

  • Never replies to the customer. It only fills fields.
  • CPF, CNPJ, email, phone and card numbers are masked before the request leaves the server.
  • Once an agent classifies a ticket by hand, the AI stops touching it.
  • Waits for the customer to stop typing, and calls for each conversation are capped.

Telegram sales bot

claude-haiku-5-5 · per channel, off by default

Talks to people in private chat and guides them to purchase.

  • Two separate switches: answer during the funnel, or after it ends.
  • "Focused" mode keeps it on the draw and the sale.
  • Can ask for a phone number, which shows up as a share-contact button.
  • If the model fails, a fixed fallback reply goes out, so nobody is left without an answer.
  • No personal data in the prompt. The webhook never waits on the model.

Voice messages

whisper-1 · Telegram audio

Incoming voice notes are transcribed so the bot and human agents can read them. Outgoing audio is converted to Telegram voice format with ffmpeg.

Claude Code as pair programmer

How it was built

I directed and decided; Claude Code wrote code against rules kept in the repo. The rules are what keep a large codebase coherent when most of it is written with AI.

Rules file for every change

AGENTS.md holds the engineering rules Claude Code must follow, for example: no hand-written colors, dates in one timezone helper, no PII in AI calls.

Decision log

ESTADO.md records why each decision was taken, with the date. New sessions read it first, so nobody reopens a settled decision.

Tests that guard the architecture

A single npm test chain runs 134 scripts. They cover the business rules, and also the architecture: one portal can't reach another's data, imports resolve, hooks run in order, and numbers on screen match the database.

Immutable migrations

216 numbered SQL files and no edits to old ones. Two Postgres schemas share one database: the existing sales schema is read-only from here.

One install per client

Built to be resold: each client company gets its own database, processes, domains and credentials, created and published with one command each.
